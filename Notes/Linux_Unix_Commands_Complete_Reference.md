## 1. Navigation & Directory Commands

| SL | Command | What it actually does | Real syntax | Common practical examples | All important flags / options |
|----|---------|------------------------|--------------|-----------------------------|-------------------------------|
| 1 | `pwd` | Prints the absolute (full) path of your current working directory. Reads from the shell's environment (`$PWD`) by default. No files are read from disk unless `-P` is used. | `pwd [OPTION]` | `pwd`<br>`pwd -P` | - `-L` — **logical**: show the path with symlinks kept as-is (default). Use: `pwd -L`<br>- `-P` — **physical**: resolve all symlinks and show the real path. Use when you need the true filesystem location. Ex: `pwd -P` |
| 2 | `ls` | Lists files and directories: names, permissions, sizes, timestamps, ownership, and recursive contents depending on flags. Without a directory argument it lists the current directory. Exit status `0` on success, `2` if a given path doesn't exist. | `ls [OPTION]... [FILE]...` | `ls`<br>`ls -la`<br>`ls -lh /var/log`<br>`ls -R project/`<br>`ls -lt`<br>`ls -S`<br>`ls d*` (wildcard) | - `-a` — **all**: shows hidden dot-files (`.bashrc`, `.git`). Ex: `ls -a`<br>- `-l` — **long format**: shows permissions, owner, group, size, mtime. Ex: `ls -l`<br>- `-h` — **human-readable**: sizes in KB/MB/GB (use with `-l`). Ex: `ls -lh`<br>- `-R` — **recursive**: lists subdirectories too. ⚠️ slow on huge trees. Ex: `ls -R`<br>- `-t` — sort by modification time, newest first. Ex: `ls -lt`<br>- `-u` — sort/show by last access time instead of mtime.<br>- `-r` — reverse the sort order. Ex: `ls -ltr` (oldest last = newest at bottom, handy for logs)<br>- `-S` — sort by file size, largest first. Ex: `ls -lS`<br>- `-d` — show info about the directory itself, not its contents. Ex: `ls -ld dir1`<br>- `-i` — show inode numbers.<br>- `-k`/`-s` — size in KB / size in blocks.<br>- `--color=auto` — colorize output by file type.<br>**Combo tip:** `ls -la | grep "^d"` to list only directories. |
| 3 | `cd` | Changes ("change directory") your shell's current working directory. With no argument, moves to your `$HOME`. It's a shell built-in, not a separate binary, so it can't be piped to. | `cd [DIRECTORY]` | `cd /var/log`<br>`cd ..`<br>`cd ~`<br>`cd -`<br>`cd` | - *(no flag)* `cd dir1` — go into `dir1`.<br>- `cd ..` — move **one level up** to the parent directory.<br>- `cd ~` or `cd` (no argument) — go to your **home directory**.<br>- `cd -` — jump back to the **previous** directory you were in (toggle).<br>- `cd /` — go to filesystem root.<br>**Note:** relative paths (`cd sub/dir`) are resolved from where you currently are; absolute paths (`cd /etc`) always start from root. |
| 4 | `mkdir` | Creates one or more new directories. Fails with a non-zero exit status if the directory already exists or if you lack write permission in the parent directory. | `mkdir [OPTION]... DIRECTORY...` | `mkdir Project`<br>`mkdir -p dir1/dir2/newdir`<br>`mkdir -m 750 secure_dir`<br>`mkdir dirA dirB dirC` | - `-p` — **parents**: creates missing parent directories along the path, and does **not** error if the directory already exists. Essential for nested paths. Ex: `mkdir -p a/b/c`<br>- `-m MODE` — set the access permissions at creation time instead of relying on the umask. Ex: `mkdir -m 700 private`<br>- `-v` — **verbose**: prints a message for every directory created. |
| 5 | `rmdir` | Deletes **empty** directories only. If the directory has any content, it fails with an error — this is a safety feature compared to `rm -r`. | `rmdir [OPTION]... DIRECTORY...` | `rmdir TestFolder`<br>`rmdir -p a/b/c` | - `-p` — remove a directory and then attempt to remove each parent directory in the path if it also becomes empty. Ex: `rmdir -p a/b/c`<br>- `--ignore-fail-on-non-empty` — don't report an error just because the directory isn't empty.<br>**Safe usage tip:** prefer `rmdir` over `rm -r` when you *intend* to delete only an empty folder — it protects you from accidentally nuking data. |

## 2. File Operations (Create, Copy, Move, Delete, Link, View)

| SL | Command | What it actually does | Real syntax | Common practical examples | All important flags / options |
|----|---------|------------------------|--------------|-----------------------------|-------------------------------|
| 6 | `touch` | Creates a new empty file if it doesn't exist, or updates the access/modification timestamp of an existing file without changing its content. | `touch [OPTION]... FILE...` | `touch notes.txt`<br>`touch -t 202601011200 file.txt`<br>`touch file1 file2 file3` | - `-a` — update only the **access** time.<br>- `-m` — update only the **modification** time.<br>- `-c` — do **not** create the file if it doesn't exist (avoids accidental creation).<br>- `-t STAMP` — set a specific timestamp instead of "now". Ex: `touch -t 202601011200 f.txt`<br>- `-r FILE` — copy the timestamp from another reference file. |
| 7 | `cat` | "Concatenate" — reads file(s) and prints their content to standard output. Used to view small files, join multiple files into one, or feed content into a pipeline. Reads from stdin if no file is given (useful with `Ctrl+D` to end input). | `cat [OPTION]... [FILE]...` | `cat file.txt`<br>`cat file1 file2 > combined.txt`<br>`cat file1 >> file2`<br>`cat -n script.sh`<br>`cat file1 file2 file3` | - `-n` — number **all** output lines.<br>- `-b` — number only non-blank lines.<br>- `-s` — squeeze multiple blank lines into one.<br>- `-A` — show all non-printing characters (tabs as `^I`, line ends as `$`) — great for spotting hidden whitespace bugs.<br>- `-E` — show `$` at end of each line.<br>**Redirection notes:** `>` overwrites the target file; `>>` appends. ⚠️ `cat file1 file2 > file1` will destroy `file1` before reading it — never redirect a `cat` into one of its own source files.<br>**Combo:** `cat file.txt | grep "error"` to filter content. |
| 8 | `more` | A classic **pager**: displays a text file one screenful at a time, moving only forward (with limited backward scroll). Superseded in practice by `less`, but still available everywhere. | `more [OPTION] FILE` | `more textfile`<br>`more -50 file.txt` | - `SPACEBAR` — page forward one screen (a keybinding, not a CLI flag).<br>- `b` — page backward one screen.<br>- `h` — show help inside the pager.<br>- `/pattern` — search forward for text.<br>- `:n` — jump to the next file (when multiple files were given).<br>- `-n NUM` — display `NUM` lines per screen instead of the terminal's default. |
| 9 | `less` *(covered here since it's the modern replacement referenced alongside `more`)* | An improved pager that lets you scroll **both forward and backward**, search, and doesn't load the whole file into memory — safe for huge log files. | `less [OPTION] FILE` | `less bigfile.log`<br>`less +F app.log` | - `/pattern` — search forward; `?pattern` search backward; `n`/`N` repeat search.<br>- `-N` — show line numbers.<br>- `-S` — don't wrap long lines (chop them, scroll sideways with arrows).<br>- `+F` — behave like `tail -f` (live-follow) but you can still scroll back.<br>- `q` — quit. |
| 10 | `cp` | Copies files or directories to a new location/name. By default, refuses to copy a directory unless `-r`/`-R` is used, and refuses to overwrite in some configurations unless forced. | `cp [OPTION]... SOURCE DEST`<br>`cp [OPTION]... SOURCE... DIRECTORY` | `cp file1.txt file2.txt`<br>`cp file3 file4 dir1/`<br>`cp -r dir2 dir3`<br>`cp -p script.sh backup/`<br>`cp -i old.conf new.conf` | - `-r`, `-R` — **recursive**: required to copy directories and their contents. Ex: `cp -r src/ dest/`<br>- `-i` — **interactive**: prompts `y/n` before overwriting an existing destination file. Recommended for safety.<br>- `-f` — ⚠️ **force**: overwrite existing files without asking, even removing a destination that can't be written to directly.<br>- `-p` — **preserve** original permissions, ownership, and timestamps in the copy.<br>- `-v` — **verbose**: print each file as it's copied.<br>- `-u` — **update**: copy only when the source is newer than the destination or destination is missing (great for sync-like copies).<br>- `-a` — **archive**: shorthand for `-dR --preserve=all`, used to fully clone a directory tree (permissions, symlinks, timestamps).<br>- `-L` (with `-R`) — if a symlink points to a directory, recurse into it instead of just copying the link.<br>**Note:** `cp` never overwrites a file with itself; copying a directory onto itself will error. |
| 11 | `mv` | Moves or renames files and directories. Since it's usually just a filesystem-metadata operation (when source/target are on the same disk), it is much faster than `cp`+`rm` and preserves permissions automatically. | `mv [OPTION]... SOURCE... TARGET` | `mv old.txt new.txt`<br>`mv file1.txt Documents/`<br>`mv dir1 dir2`<br>`mv *.log logs/`<br>`mv -i report.docx final/` | - `-i` — **interactive**: ask before overwriting an existing target. Recommended.<br>- `-f` — ⚠️ **force**: overwrite without prompting.<br>- `-u` — **update**: move only if source is newer than an existing destination file, or destination doesn't exist.<br>- `-v` — **verbose**: print what was moved.<br>- `-n` — **no-clobber**: never overwrite an existing file.<br>**Behavior table:** file → new name = rename; file → existing file = overwrite; directory → new name = rename; directory → existing directory = moved **inside** it as a subdirectory; multiple files → existing directory = all moved into it. |
| 12 | `rm` | Permanently deletes files (and, with `-r`, directories). There is **no recycle bin** in the shell — deleted data is gone unless you have a backup or use special recovery tools. | `rm [OPTION]... FILE...` | `rm demo.txt`<br>`rm -i *.tmp`<br>`rm -rf build/` ⚠️<br>`rm -v old_logs/*.log` | - `-i` — **interactive**: prompt for confirmation on every file. Strongly recommended for beginners: `alias rm='rm -i'`.<br>- `-f` — ⚠️ **force**: never prompt, ignore nonexistent files and errors. Very dangerous when combined with `-r`.<br>- `-r`, `-R` — **recursive**: delete directories and everything inside them.<br>- `-rf` — ⚠️⚠️ the most destructive common combo: silently and recursively deletes everything matched, no confirmation. Always double-check the path (and never run as root on `/` or with an empty/unset variable in the path, e.g. `rm -rf $VAR/` when `$VAR` is empty deletes root-level files).<br>- `-v` — verbose, prints each deletion.<br>- `-d` — remove empty directories too (like `rmdir`) without needing `-r`.<br>**Safe tip:** run `ls` on the same glob first to preview exactly what will be deleted before running `rm`. |
| 13 | `ln` | Creates **links** between files. A **hard link** is another name for the same inode (same data, no shortcut behavior, must be same filesystem). A **symbolic (soft) link** is a pointer/shortcut file that can cross filesystems and can point to directories. | `ln [OPTION] TARGET LINK_NAME` | `ln -s file1.txt link1.txt`<br>`ln original.txt hardlink.txt`<br>`ln -s /var/www/html public_html` | - `-s` — create a **symbolic link** instead of a hard link (most commonly used form). Ex: `ln -s target linkname`<br>- `-f` — force: remove an existing destination file first if it exists.<br>- `-v` — verbose.<br>**Note:** deleting the *original* file breaks a symlink (dangling link) but a hard link keeps working since it shares the same inode/data until all hard links are removed. |
| 14 | `head` | Prints the **first** lines of a file (default: first 10 lines). Useful for quickly previewing large files without opening the whole thing. | `head [OPTION]... [FILE]...` | `head file.txt`<br>`head -n 50 access.log`<br>`head -c 200 data.bin` | - `-n NUM` — show the first `NUM` lines instead of 10. Ex: `head -n 5 file.txt`<br>- `-c NUM` — show the first `NUM` bytes instead of lines.<br>- `-q` — quiet: don't print filename headers when multiple files given.<br>- `-v` — always print filename headers, even for a single file.<br>**Combo:** `head -n 20 bigfile.csv` to peek at a huge CSV before loading it into a script. |
| 15 | `tail` | Prints the **last** lines of a file (default: last 10). Most famous for `-f`, which "follows" a growing file live — the standard way to watch log files in real time. | `tail [OPTION]... [FILE]...` | `tail file.txt`<br>`tail -n 20 access.log`<br>`tail -f /var/log/syslog`<br>`grep '<title>' file \| tail -n 20` | - `-n NUM` — show the last `NUM` lines. Ex: `tail -n 100 error.log`<br>- `-f` — **follow**: keep the terminal open and print new lines as they're appended (essential for live log monitoring). Stop with `Ctrl+C`.<br>- `-F` — like `-f` but also re-attaches if the file is rotated/recreated (used for logs that get rotated by `logrotate`).<br>- `-c NUM` — show the last `NUM` bytes. |
| 16 | `vi` | The classic modal command-line text editor. Two core modes: **Insert (Input) mode** for typing text, and **Edit (Command/Normal) mode** for navigation, deleting, searching, and saving. Opens a file (creating it if it doesn't exist) directly in the terminal. | `vi [FILE]` | `vi Firstfile`<br>`vi /etc/hosts` | Key actions (not CLI flags, but essential in-editor commands):<br>- `i` — enter insert mode to start typing.<br>- `Esc` — return to normal/edit mode from insert mode.<br>- `ZZ` (capital, no colon) — **save and exit**.<br>- `:w` — save (write) without exiting.<br>- `:wq` or `:x` — save and exit.<br>- `:q!` — **discard all unsaved changes** and exit. ⚠️ irreversible for unsaved edits.<br>- `/pattern` — search forward for text; `n` repeats search.<br>- `dd` — delete the current line; `yy` — copy (yank) the current line; `p` — paste.<br>**Tip:** check the bottom-left corner of the screen — if it doesn't say `INSERT`, you're safely in edit/normal mode. |

## 3. Search, Filtering & Text Processing

| SL | Command | What it actually does | Real syntax | Common practical examples | All important flags / options |
|----|---------|------------------------|--------------|-----------------------------|-------------------------------|
| 17 | `find` | Searches a directory tree for files/directories matching conditions (name, type, size, modification time, owner, etc.) and can execute actions on the matches. Extremely powerful for automation. | `find [PATH...] [CONDITIONS] [ACTION]` | `find . -name '*.f'`<br>`find /home -name chapter1`<br>`find /home /usr -name 'memo*' -user ann`<br>`find / -mtime -2`<br>`find / -size +10M`<br>`find . -type f -exec rm {} \;` ⚠️ | - `-name PATTERN` — match by filename (case-sensitive); use quotes so the shell doesn't expand wildcards early. Ex: `find . -name '*.log'`<br>- `-iname PATTERN` — case-insensitive name match.<br>- `-type f/d/l` — filter by type: file, directory, or symlink.<br>- `-size N[kMG]` — filter by size (`+` larger than, `-` smaller than). Ex: `find / -size +100M`<br>- `-mtime N` — modified N days ago (`-2` = within last 2 days, `+2` = more than 2 days ago).<br>- `-user NAME` — owned by a specific user.<br>- `-print` — explicitly print matching paths (default action on most systems, but some old Unix variants require it).<br>- `-exec CMD {} \;` — run a command on each match, `{}` is replaced by the filename. ⚠️ combined with `rm` this is destructive — test first with `-print`.<br>- `-delete` — delete matches directly (faster than `-exec rm`). ⚠️ irreversible.<br>**Combo tip:** `find . -name '*.tmp' -print` first to preview, **then** add `-delete`. |
| 18 | `locate` | Finds files by name almost instantly by searching a **prebuilt index database** (instead of walking the live filesystem like `find`). Much faster, but the index can be stale until refreshed. | `locate [OPTION] PATTERN` | `locate demo.txt`<br>`locate -i readme` | - `-i` — case-insensitive search.<br>- `-c` — print only the **count** of matches instead of paths.<br>- `-l NUM` — limit output to `NUM` results.<br>**Requirement:** the database must exist/be current — run `updatedb` (usually needs root/sudo) to refresh it, otherwise `locate` won't find recently created files. |
| 19 | `whereis` | Locates the **binary, source, and manual page** files for a command — tells you *where* a program and its docs physically live, not just whether it's on your `PATH`. | `whereis [OPTION] COMMAND` | `whereis ls`<br>`whereis -b python3` | - `-b` — show only the binary location.<br>- `-m` — show only the manual page location.<br>- `-s` — show only source file location. |
| 20 | `which` | Shows the exact path of the executable that **would run** if you typed a command name — resolves your `$PATH` and shell aliases, useful for debugging "wrong version is running" issues. | `which [OPTION] COMMAND` | `which python3`<br>`which -a python` | - `-a` — show **all** matching executables found in `$PATH`, not just the first one. Ex: `which -a python` (useful when multiple Python versions are installed). |
| 21 | `grep` | "Global Regular Expression Print" — searches text (files or stdin) for lines matching a pattern and prints matching lines. One of the most-used commands in all of Unix for filtering output. | `grep [OPTION] "PATTERN" FILE...` | `grep "Python" notes.txt`<br>`grep -i error log.txt`<br>`grep -c motif1 file1`<br>`grep -v motif1 file1`<br>`ps aux \| grep nginx` | - `-i` — case-insensitive search.<br>- `-v` — **invert match**: show lines that do **not** match.<br>- `-c` — print only the **count** of matching lines.<br>- `-n` — show line numbers along with matches.<br>- `-r`/`-R` — recursive search through a directory tree.<br>- `-l` — print only the **filenames** that contain a match (not the lines).<br>- `-w` — match whole words only.<br>- `-A NUM` / `-B NUM` / `-C NUM` — show `NUM` lines of context **after** / **before** / **around** each match.<br>- `-E` — enable extended regex (same as `egrep`).<br>**Combo:** `dmesg | grep -i error` or `cat access.log | grep "500" | wc -l`. |
| 22 | `egrep` | **Extended grep** — like `grep` but with extended regular expressions enabled by default, so metacharacters like `+`, `?`, `()`, `|` work without escaping. Functionally equal to `grep -E`. | `egrep [OPTION] 'REGEXP' FILE` | `egrep '(Victor|Victoria)' file`<br>`egrep -n 'error+' log.txt` | - `-n` — print the matching line number.<br>- `-v` — print lines that do **not** match.<br>**Note:** on modern systems `egrep` is deprecated in favor of `grep -E`, but still works identically. |
| 23 | `fgrep` | **Fast/fixed grep** — searches for a **literal string** (no regex interpretation at all), so special characters like `.` or `*` are treated as plain text. Equivalent to `grep -F`. Same option set as `egrep`. | `fgrep [OPTION] 'PATTERN' FILE` | `fgrep "192.168.1.1" access.log`<br>`fgrep -c "TODO" *.py` | - Options are the same as `egrep` (`-n`, `-v`, `-c`, etc.).<br>**When to use:** when your search string itself contains regex-special characters (like IP addresses with dots) and you don't want them interpreted. |
| 24 | `sed` | **Stream editor** — edits text non-interactively using scripted commands (substitute, delete, print) applied line by line, without opening the file in an editor. Core tool for automated text transformation. | `sed [OPTION] 'SCRIPT' FILE` | `sed 's/foo/bar/' file.txt`<br>`sed -i 's/old/new/g' config.conf`<br>`sed -e '2d' file.txt` | - `-e SCRIPT` — apply an explicit editing script/instruction (can be repeated for multiple edits).<br>- `-f SCRIPTFILE` — read editing instructions from a file instead of the command line.<br>- `-i` — ⚠️ **edit in place**: overwrites the original file directly (use `-i.bak` to keep a backup, e.g. `sed -i.bak 's/a/b/' file`).<br>- `-n` — suppress automatic printing (used with the `p` command to print only selected lines).<br>- `s/old/new/g` — the classic substitute pattern (`g` = replace **all** occurrences on the line, not just the first).<br>**Combo:** `grep -l "foo" *.txt | xargs sed -i 's/foo/bar/g'` to bulk find-and-replace across many files. |
| 25 | `sort` | Sorts the lines of a file (or stdin) alphabetically by default; can sort numerically, in reverse, by specific columns, and remove duplicates. | `sort [OPTION] [FILE]` | `sort test.txt`<br>`sort -r file.txt`<br>`sort -n numbers.txt`<br>`sort -u names.txt`<br>`sort -k2 data.csv` | - `-d` — **dictionary order**: ignore punctuation, sort only on letters/digits/spaces.<br>- `-r` — reverse the sort order (descending).<br>- `-n` — **numeric sort**: sorts by actual numeric value instead of string/lexical order (essential — without it, "10" sorts before "2").<br>- `-u` — unique: remove duplicate lines from the output.<br>- `-k N` — sort by the `N`th column/field instead of the whole line. Ex: `sort -k2 -n data.txt`<br>- `-t CHAR` — set the field delimiter (default is whitespace). Ex: `sort -t',' -k3 file.csv`<br>- `-f` — case-insensitive sort (fold case).<br>**Combo:** `sort file.txt | uniq -c | sort -nr` — a classic "count and rank" pipeline. |
| 26 | `wc` | "Word count" — counts lines, words, and characters/bytes in a file (or stdin). Output order is: lines, words, characters, filename. | `wc [OPTION]... [FILE]...` | `wc test.txt`<br>`wc -l file.txt`<br>`ls \| wc -l`<br>`wc -w essay.txt` | - `-l` — count only **lines**. Very commonly used, e.g. `wc -l` to count how many results a command returned.<br>- `-w` — count only **words**.<br>- `-c` — count only **bytes/characters**.<br>- `-m` — count characters (respects multibyte/UTF-8 encoding, unlike `-c`).<br>**Combo:** `find . -name '*.py' | wc -l` to count how many Python files exist. |
| 27 | `diff` | Compares two files (or two directories) line by line and reports the differences needed to transform one into the other. Output uses `<` for lines only in file1 and `>` for lines only in file2. | `diff [OPTION] FILE1 FILE2` | `diff file1.txt file2.txt`<br>`diff -b old.conf new.conf`<br>`diff -u a.py b.py`<br>`diff -r dir1 dir2` | - `-b` — ignore differences in blank/whitespace amount.<br>- `-e` — output an `ed`-editor script that would transform file1 into file2.<br>- `-c NUM` / `-C NUM` — context-diff format, showing `NUM` lines of surrounding context, with `+`/`-`/`!` markers for added/removed/changed lines.<br>- `-u` — **unified diff** format (the format used in patch files / git diffs) — most human-readable for code review.<br>- `-r` — recursively compare two directories.<br>- `-D SYMBOL` — merge both files into one with C-preprocessor `#ifdef` conditionals. |
| 28 | `cmp` | A simpler, byte-level comparison of two files. Instead of showing line differences, it just reports **whether** they differ and the exact byte/line position of the first difference. Exit status: `0` = identical, `1` = different, `2` = inaccessible/error. | `cmp [OPTION] FILE1 FILE2` | `cmp file1 file2`<br>`cmp -s a.bin b.bin && echo same` | - `-s` — **silent**: suppress output, just set the exit status (useful in scripts/conditionals).<br>- `-l` — list **every** byte that differs, with its offset and values in both files (verbose, byte-by-byte). |
| 29 | `comm` | Compares two **already-sorted** files line by line and prints results in three columns: lines unique to file1, lines unique to file2, and lines common to both. | `comm [OPTION] FILE1 FILE2` | `comm file1 file2`<br>`comm -12 file1 file2`<br>`comm -23 file1 file2` | - `-1` — suppress column 1 (lines unique to file1).<br>- `-2` — suppress column 2 (lines unique to file2).<br>- `-3` — suppress column 3 (common lines).<br>- `-12` — show **only** lines common to both files (suppress columns 1 & 2).<br>- `-23` — show only lines unique to file1.<br>**Requirement:** both input files must be sorted first (`sort file1 > f1.sorted`), or results will be wrong. |

## 4. Permissions & Ownership

| SL | Command | What it actually does | Real syntax | Common practical examples | All important flags / options |
|----|---------|------------------------|--------------|-----------------------------|-------------------------------|
| 30 | `chmod` | "Change mode" — changes the **read/write/execute** permissions of a file or directory for the owner (`u`), group (`g`), and others (`o`). Can use symbolic (`u+x`) or numeric/octal (`755`) notation. Only the owner or a privileged (root) user can change a file's mode. | `chmod [OPTION] MODE FILE...` | `chmod u+x script.sh`<br>`chmod 751 file`<br>`chmod g+wx frog.png`<br>`chmod go-x frog.png`<br>`chmod -R 644 project/` | **Symbolic mode components:**<br>- **who**: `u` (user/owner), `g` (group), `o` (others), `a` (all)<br>- **operator**: `+` (add permission), `-` (remove permission), `=` (assign exactly, removing anything not listed)<br>- **permission**: `r`/`4` (read), `w`/`2` (write), `x`/`1` (execute)<br>**Numeric mode:** sum the values per group — e.g. `751` = owner `rwx`(7), group `r-x`(5), others `--x`(1). `chmod 751 file` ≡ `chmod u=rwx,g=rx,o=x file`.<br>- `-R` — recursive: apply to a directory and everything inside it. ⚠️ be careful applying execute bits recursively to plain files.<br>- `-f` — quiet (suppress error messages).<br>- `-v` — verbose, print what changed.<br>**Script use:** `chmod +x script.sh` is the standard way to make a shell script runnable via `./script.sh`. |
| 31 | `chown` | Changes the **owner** (and optionally the group) of one or more files. **Permissions concept recap (from GUB tutorial):** every file has 3 permission types (`r` read, `w` write, `x` execute) for 3 categories of people (**owner**, **group**, **others**). View them with `ls -l` — e.g. `-rwxr-x--x` means owner=read/write/execute, group=read/execute, others=execute-only.

## 12. Wildcards & Shell Globbing (Concept Reference — Not a Command)

Wildcards let you refer to a **set** of files/directories in one pattern when used with commands like `ls`, `rm`, `cp`, `mv`.

| Symbol | Meaning | Example | What it matches |
|--------|---------|---------|------------------|
| `*` | zero or more characters | `ls b*` | any name starting with `b` |
| `?` | exactly one character | `ls ?i*` | any name with `i` as the 2nd character |
| `[...]` | a range/set of characters | `ls [sv]*` | names starting with `s` or `v` |
| `[a-v]*` | a character range | `ls [a-v]*` | names starting with any letter a through v |
| `*[0-9]*` | any digit anywhere in the name | `ls *[0-9]*` | filenames containing at least one digit |

⚠️ Combined with `rm`, wildcards are dangerous — always preview with `ls` on the same pattern before running `rm` on it.

## Quick Safety Cheat-Sheet (Recap)

- ⚠️ `rm -rf` — irreversible recursive force-delete. Preview with `ls` first, never run on an unset/empty variable path.
- ⚠️ `kill -9` — un-catchable forced kill, no cleanup. Try plain `kill` (SIGTERM) first.
- ⚠️ `chmod -R` / `chown -R` — recursive permission/ownership changes can break running services if misapplied.
- ⚠️ `sed -i` — edits files in place; use `-i.bak` to keep a backup copy.
- ⚠️ `dd`, `mkfs`, `umount -f` (not detailed above but frequently paired with these topics) — always double, triple-check the target device.
- ⚠️ `rsync --delete` and `find -delete` — always run with `--dry-run` / without `-delete` first to preview.
- ✅ General habit: for any destructive command, run the "preview" version (`ls`, `find ... -print`, `--dry-run`) before the real one.
